= 持续游玩卡顿：绘制缓存修复与验证
:toc: left
:toclevels: 2
:sectnums:

== 问题与范围

用户反馈运行一段时间后卡顿，尤其是玩家跟不上鼠标。鼠标处理原本直接设置玩家坐标，没有缓动；排查发现，战斗与背景频繁从高分辨率 PNG 缩放到实际显示尺寸，成为受限 CPU 条件下的绘制热点。

普通运行路径及两场景各 80 秒的初步采样未发现游戏对象持续累积。这里修复已验证的重复缩放开销，不把未复现的设备或浏览器问题归结为内存泄漏。

== 实现

* `index.html` 仅新增加载期 `createRenderAsset`，在素材加载完成时生成内存画布，并写入现有 `assets`；主循环和鼠标处理不变。
* 角色、弹幕、特效和投影的大图按比例缓存为最长边 256 像素；小图、UI 图标和长激光束保留原图。
* 俯视水面和斜视底图缓存为 1280 × 720；两层固定尺寸云缓存为 576 × 192、704 × 235。斜视景物的连续透视缩放保留原图。
* 保留透明背景和像素采样。缓存随页面加载建立，重开游戏复用同一对象；未修改原 PNG、素材清单、玩法数值或历史版本。

== 回归测试

新增 5 项行为测试先因缺少生产缓存函数失败，其余 73 项通过；实现后 `node --test tests/game-logic.test.mjs` 为 78/78。

测试覆盖缓存尺寸、透明画布与像素采样、原图例外、预加载完成后可用，以及绘制和重开时对象复用。浏览器烟测通过实际 `drawImage` 来源检查缓存对象身份和重开复用。

完整 `tests/browser-smoke.py` 执行通过，覆盖 1280 × 720 与 1440 × 900、两场景、成长、通关、无尽、重开、持续动画和素材加载，无控制台错误或外部请求。

新增 `tests/browser-performance.py`，通过浏览器响应注入诊断，不向产品加入性能日志，也不启用会持续追加记录的游戏测试模式。采样数组每个窗口清空，断言鼠标最终坐标、输入样本数量、对象数量、画布创建数及缓存身份/尺寸稳定。

== 性能证据

=== 条件与口径

本机 Chromium headless、1280 × 720、CDP 4 倍 CPU 限速、8 个持续存活的无人机、3 级追踪导弹及持续鼠标移动。修复前后按同一场景初始化并顺序执行，未同时运行其他浏览器测试。

表格是每个 10 秒窗口的 P95 的范围，不是所有帧合并后的 P95。绘制耗时衡量 JavaScript 绘制调用耗时；输入耗时从鼠标事件时间戳到绘制调用结束，不等于显示器的真实光学延迟。结果用于同机对照，不代表所有设备的固定帧率。

=== 各场景 60 秒持续运行

[cols="1,1,1,1,1",options="header"]
|===
|场景 |修复前绘制 P95 / ms |修复后绘制 P95 / ms |修复前输入 P95 / ms |修复后输入 P95 / ms
|俯视 |11.1–18.4 |1.2–1.5 |25.8–35.1 |16.4–17.0
|斜视 |19.0–37.0 |1.2–8.0 |36.8–121.4 |16.4–22.8
|===

修复后两场景各 60 秒期间，36 张缓存对象始终复用，缓存像素总数固定为 3,648,832，战斗中没有新增画布；游戏数组数量有界。回收后 JS 堆约 1.67–1.76 MiB，无持续增长趋势。该数值不包含完整图像解码、GPU 或浏览器进程内存。

原始数据：link:render-cache-validation/sustained-metrics.json[持续运行采样]。

=== 排除预热和采样干扰的复核

持续运行采样中的强制 GC 可能影响下一个窗口的首帧，因此进一步修正诊断脚本：每个版本使用独立浏览器进程，预热 10 秒后重新初始化同一战斗状态；每次 GC 与堆采样结束后清空计时窗口。每场景复核 20 秒，输入样本数均超过 100。

[cols="1,1,1,1,1",options="header"]
|===
|场景 |修复前绘制 P95 / ms |修复后绘制 P95 / ms |修复前输入 P95 / ms |修复后输入 P95 / ms
|俯视 |9.8–10.4 |1.1–1.2 |24.8–25.6 |16.9
|斜视 |15.4–16.6 |1.2 |30.9–32.7 |16.6–16.9
|===

原始数据：link:render-cache-validation/controlled-metrics.json[预热后复核采样]。

独立的“事件处理函数开始到绘制结束”指标也记录在 JSON 的 `handledInputP95` 中，避免混淆事件排队与绘制本身的开销。

== 画面检查

固定游戏时间、敌人位置、武器与特效，比较两场景实际画布截图。检查角色轮廓与颜色、背景、透明投影、敌弹、命中特效和长激光束，未发现缺图、错位或明显画质退化。预缩放会改变部分采样像素，不宣称逐像素一致。

== 复验方式

先启动本机 HTTP 服务，再运行：

[source,shell]
----
node --test tests/game-logic.test.mjs
python3 tests/browser-smoke.py
python3 tests/browser-performance.py --seconds 60 --cpu-rate 4
----

需要与保留的旧源码对照时，追加 `--baseline /path/to/old-index.html`。性能阈值受机器负载影响，探针输出测量结果，不以固定 FPS 门槛替代回归检查。
