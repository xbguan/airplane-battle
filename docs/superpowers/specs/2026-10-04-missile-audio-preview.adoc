== 范围与当前状态

2026-10-04：用户确认制作导弹发射音效试听，并要求在全部资产清单中增加可点击试听的音效清单。用户试听确认后，0.4 秒新版导弹声已接入游戏，清单同步显示当前运行状态；保留旧版试听用于历史对比。

* 当前声音由 `index.html` 的 `createSoundBuffer` 生成并缓存，不依赖外部音频文件。
* 当前清单仅展示 12 项实际使用的音效，位置在“独立投影”之前；已移除 `fire` 试听条目与独立导弹历史对比区。历史试听文件和记录保留，当前基础射击使用 `machinegun`。
* 每项声音显示用途、时长与使用状态，提供原生播放控件；开始播放另一项时暂停上一项。
* `docs/superpowers/specs/previews/runtime-audio/` 保存从当前生产函数导出的 13 项 WAV，仅用于清单试听。

== 导弹候选方向

原声为 0.14 秒升调锯齿波。候选改为 0.4 秒的一次性发射声，组合低频点火、克制的滤波喷气噪声与渐弱呼啸；不恢复历史上因杂音移除的持续飞行推进声。

新版为程序合成，在首次发射时写入 AudioBuffer，后续发射复用缓存并在播放完成时断开节点；不改变战斗数值或武器发射间隔。

== 试听与复现

试听文件位于 `docs/superpowers/specs/previews/missile-audio/`：

* `original.wav`：当前导弹单发声音。
* `candidate.wav`：0.4 秒候选声音。
* `comparison.wav`：原声、0.35 秒静音、新声依次播放。
* `battle-original.wav` 与 `battle-candidate.wav`：各 6 秒，机枪每 0.09 秒、导弹每 1.5 秒播放，原始增益一致，不做归一化；这是机枪与导弹的受控对比混音，不包含敌人和爆炸声。

重新导出试听与指标：

[source,shell]
----
node docs/superpowers/specs/previews/missile-audio/generate-preview.mjs
----

脚本读取当前生产声音函数，借助 AudioBuffer 桩执行，不修改生产代码。新版与爆炸预览使用固定随机种子，以便复现；游戏中随机爆炸音的细节可能不同。原版对比使用冻结的旧算法，避免再次导出时覆盖历史声音。未来修改运行声音后，须同步重新导出并更新清单的时长、描述及状态。

== 试听阶段验证

* Sol 子代理完成合成、导出与波形检查；主代理独立检查实际 WAV、浏览器解码与播放交互。
* 18 个 WAV 均为单声道、44.1 kHz、16 位 PCM；全部可解码、有非零信号、无削波。
* 候选在 22.05、44.1、48 kHz 下通过长度、有限值、首尾归零与确定性检查。
* 44.1 kHz 候选峰值约 -17.28 dBFS；候选机枪混音峰值约 -11.97 dBFS。指标不替代用户对听感的判断。
* 清单 18 个播放器全部加载，浏览器实际点击播放与切换自动暂停通过，无页面脚本或控制台错误；600 像素宽度无横向溢出。
* 游戏规则测试 45/45 通过。本轮未更改运行代码，未执行游戏全量浏览器烟测。

== 确认接入验证

* Sol 子代理按测试先失败、再实现的顺序接入 `createSoundBuffer`；主代理核对代码与实际浏览器输出。
* 新版合成参数及随机种子保持已确认试听版本；`runtime-audio/missile-launch.wav` 与已确认 `candidate.wav` 字节一致。重新导出后，仅当前导弹试听 WAV 改变，其余声音与历史对比 WAV 均保持原 SHA-256。
* 规则测试 48/48 通过，覆盖试听逐采样对照、缓存复用与结束释放、机枪和激光声音不变。
* 浏览器实际触发 3 次导弹发射，仅创建 1 个导弹 AudioBuffer，3 次复用同一缓存且均结束断开；44100 Hz 实际输出与确认算法逐采样一致，发射间隔约 1.51 秒，无控制台错误。
* 清单维护仍使用 WAV 试听，游戏不新增外部音频请求；旧版清楚标记为历史对比。
